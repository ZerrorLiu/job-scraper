# Repository accumulation controls

## Outcome

Successive agent sessions had left the tree carrying material that no longer
described the running system: a quarantined pre-v2 test suite, pre-refactor
track configurations, logs and outputs from one-off migrations finished in July
2026, an empty deployment directory, stale build artifacts, and bytecode for
some thirty modules that had already been deleted. None of it was reachable
from any entry point, and each item cost a reader time before it could be
dismissed.

The cause was structural, not incidental. Nothing in the repository's rules
said that superseded material must be removed by the change that supersedes it,
so every session's cheapest correct move was to add beside rather than edit in
place.

After this change the tree contains only live material, and the rule that keeps
it that way is stated in `AGENTS.md`, executed as a step in the development
workflow, required by the specification template, and enforced by tests.

## Scope

- In scope: remove regenerable artifacts; archive superseded never-versioned
  material under `local/`; restructure `.gitignore` around that distinction;
  remove a private hostname from `.env.example`; add the "extend before you
  add" rule and its survey step to `AGENTS.md`, the development workflow, and
  the project skill; add a replacement field to the specification template; add
  repository-structure invariants to the public contract test.
- Out of scope: any change to runtime behavior, the CLI surface, the
  configuration schema, or the domain. The deprecated hidden `--enable-indeed`
  flag and the legacy `jobs/run_daily.py` and `jobs/run_all_tracks.py` entry
  points are left in place; both are load-bearing in current tests and removing
  them is a behavior change that needs its own spec.

## What this change replaces

Nothing in the live package. It removes material that was already superseded
and had been left in place:

| Removed or archived | Superseded by |
|---|---|
| `tests/` (pre-v2 suite, quarantined and non-importing) | `public_tests/` |
| `config/legacy/` (four pre-refactor track TOMLs) | profiles generated by `job-scraper init` |
| `logs/`, `outputs/` (July 2026 one-off migration runs) | nothing; the runs are finished |
| `deploy/` (empty), `build/`, `.coverage`, `*.egg-info/`, all `__pycache__/` | regenerated by the toolchain |

The regenerable artifacts are deleted. The rest was never in version control,
so it is archived under `local/` with a README stating what replaced it, rather
than deleted irreversibly.

## Acceptance criteria

- [x] No directory in the working tree is unreachable from an entry point,
      the test suite, or the documented archive.
- [x] `AGENTS.md` states that changing an existing thing is the default and
      that creating a new one must be justified.
- [x] The development workflow contains a survey step that runs before
      implementation, and the specification template requires naming what a
      change replaces.
- [x] Root Markdown is limited to the four standard files, `docs/` holds only
      the current public contract, no two public documents differ only by
      separator or case, no module coexists with the version it replaces, and
      every relative documentation link resolves — each asserted by a test.
- [x] Each invariant test was observed failing against a deliberate violation.
- [x] `.env.example` names no host, workspace, or machine.
- [x] The quality gates pass and the privacy boundary is unchanged.

## Design and constraints

The rule is placed where an agent will actually meet it: `AGENTS.md` as law,
the workflow as an executable step with the searches written out, the skill as
the procedure, the spec template as the field that cannot be left blank, and
the contract test as the check that fails. Prose alone had already been tried —
the pre-v2 archives each carried a README saying they were superseded, and they
still accumulated.

The invariants live in `public_tests/test_public_contract.py` rather than in a
new file, because that file already asserts what must *not* exist in the public
surface — that a removed feature's CLI command and database tables stay gone.
Repository layout is the same kind of claim. Adding a separate file for it
would have been the first violation of the rule being introduced.

The version-coexistence check tests for pairs, not for suffixes: `sqlite_v2` is
legitimate precisely because `sqlite_v1` was removed when it landed. A suffix
ban would have punished the correct outcome.

`.gitignore` is reorganized around why each entry is ignored — private
workspace, credentials, local-only material, regenerable artifacts — because
the previous flat list gave no signal about which category a new entry belonged
in. The now-unnecessary `/tests/` rule is dropped so that a future `tests/`
directory appears in `git status` instead of being silently hidden.

`.env.example` referred to a receiver "running on vps-dev". A machine name is a
workspace identifier, and the privacy boundary excludes those from public
files.

## Verification

- `uv run ruff format --check .`, `uv run ruff check .`, `uv run pyright`, and
  `uv run pytest` — all pass; 233 tests before this change, 238 after.
- Reachability analysis over `src/` from the console script, the `jobs/`
  modules, and `public_tests/`: no unreachable module, before or after.
- Each new invariant was verified by introducing a violation — a stray
  `docs/*.md`, a separator-only duplicate name, a `config_v2.py` beside
  `config.py`, and a dead link — confirming four distinct failures, then
  reverting.
- `git status --ignored` confirms the private workspace, credentials, and the
  `local/` archive remain ignored, and that no private file became trackable
  through the `.gitignore` restructure.
- No user-path simulation: no runtime behavior, CLI surface, or configuration
  contract changed.

## Follow-ups

- `--enable-indeed` is hidden with `argparse.SUPPRESS` but still accepted by
  `run`, `run_daily`, and `run_all_tracks`. It is guarded by
  `BRIGHTDATA_DIRECT_COLLECTION_ENABLED` and asserted by
  `test_brightdata_suspension`. Removing it is a behavior change; it needs its
  own spec stating the removal condition.
- `jobs/run_daily.py` and `jobs/run_all_tracks.py` remain as pre-CLI entry
  points that `cli/main.py` wraps. Folding them into the CLI would remove a
  duplicated argument surface, and is likewise its own change.
